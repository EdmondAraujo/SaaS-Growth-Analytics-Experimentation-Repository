# SaaS Growth Analytics & Experimentation Repository

Production-ready semantic layer, self-service BI configuration and statistical
engine for a SaaS growth team. Three pillars, one contract: **the funnel and
every A/B decision must be auditable end-to-end.**

---

## Business Problem

Growth teams ship experiments faster than they can verify them. The three most
expensive failure modes are:

1. **Invalid traffic splits (SRM)** — a statistically imbalanced split silently
   poisons every metric computed on top of it.
2. **Underpowered reads** — teams kill or ship experiments on noise.
3. **Metric drift** — the number Marketing shows Leadership does not match the
   warehouse definition, eroding trust.

This repository eliminates all three by design: dbt owns the definitions,
Lightdash consumes them, and the Python engine refuses to read out results
before the SRM gate passes.

## Funnel Model

```
 Visitor ──▶ Trial ──▶ Activated ──▶ Paid
   └── acquisition_channel, plan_type carried on every stage
```

| Stage       | Definition (warehouse truth)                          |
|-------------|-------------------------------------------------------|
| `visitor`   | Row exists in `analytics_raw.funnel_events`               |
| `trial`     | User started a trial within 30 days of first visit    |
| `activated` | Trial user hit activation event (logged 3+ sessions)  |
| `paid`      | Trial user converted to a paid plan (`mrr_usd > 0`)   |

A/B allocation: 50/50 (`control` / `treatment`), assigned at first visit with
deterministic hashing — no peeking bias.

## Dataset Contract (BigQuery)

| Layer            | BigQuery dataset  | Owner                |
|------------------|-------------------|----------------------|
| Sources (raw)    | `analytics_raw`   | Ing/ETL pipelines    |
| Staging + marts  | `analytics`       | dbt (this repo)      |

`ad_spend` lives as `analytics_raw.daily_spend` (`spend_date`, `channel`,
`daily_spend`); CAC is computed in `fct_channel_spend` on a (month, channel)
join — never lifetime-mixed.

## How To Run

```bash
pip install -r requirements.txt
python src/main.py        # exit 0 = readout issued; exit 2 = SRM gate blocked
python -m pytest tests/ -q
```

Exit codes of the stat engine: `0` — readout emitted; `2` — SRM gate failed
(business metrics suppressed, diagnostic payload in `results/ab_payload_blocked.json`).
Each run deletes the artifacts of the opposite regime first, so consumers of
the default file names never read a stale result from the other regime.

The engine, without any keys, runs a **dry-run readout**: it prints the full
statistical payload plus a heuristic executive decision. With
`ANTHROPIC_API_KEY` set, the same payload is sent to the Claude API for a
written executive summary; any API failure falls back to the local heuristic
readout. The statistics are identical either way — the LLM narrates, it never
computes.

## Business Impact

- **CAC down:** channel-level `cac` metric exposes paid acquisition spend that
  never converts past the trial wall.
- **Decision velocity up:** experimentation SLA — SRM gate runs in seconds,
  so invalid reads are killed before anyone tribal-knowledges them.
- **Governance:** every metric on the dashboard traces back to a tested dbt
  column. No orphan dashboards, no self-service drift.

## Statistical Guarantees

| Check                | Method                          | Gate                       |
|----------------------|---------------------------------|----------------------------|
| Sample Ratio Mismatch| Chi-square (α=0.05); binomial exact two-sided IS the gate for cells ≤30 | Readout blocked if p < α, exit 2 |
| Conversion lift      | Two-proportion z-test, pooled SE, two-sided | α = 0.05                 |
| Power                | Post-hoc power + required N **per arm** for MDE = 2pp at 80% power: n = 2·(z_α+z_β)²·p̄(1−p̄)/MDE² | Target 0.80            |

Decisions emitted by the engine: `SHIP`, `KEEP_RUNNING` (significant but
underpowered), `ITERATE` (underpowered and not significant), `RERUN` (SRM
failure — traffic integrity first, business questions second).
